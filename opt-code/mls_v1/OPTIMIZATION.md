# MLS 下一版本优化计划

更新日期：2026-11-03。本文是基于 `mls_v1` 的下一版本实施计划，暂称 `mls_v2`，
不是已完成的功能或性能结论。算法依据见 [参考资料](REFERENCES.md)，当前实测范围
见 [验证记录](VALIDATION.md)。

下一版优先解决两个问题：**候选预测是否符合实际布线，以及不同候选对全设计
TNS 的贡献是否被正确区分。** 主线是“真实 GRT 资源与路由树 → 终点收益筛选 →
两 HBT 联合选址 → 少量候选 GRT/STA 验证 → 更新资源和边际收益”。

## 1. 当前证据与优化目标

`bp_fe` 的四网方案完整评估合法，TNS 严重程度下降约 1.44%、WNS 严重程度下降
约 4.48%，但 DRC 增加约 1.36%；单网方案有更好的 WNS、DRC 和线长。
这些是已有运行记录，不代表八个用例的普遍趋势，也不能据此认定拥塞优化必然改善时序。

本地四网方案选中的候选，其自身时序代理收益均为负，约为 −0.96%～−6.61%，
综合代理收益则为正，主要由拥塞项贡献。这里要区分：

- 当前 `D` 是单网各 sink 的最大关键性加权 Elmore 延迟，不是全设计 TNS/WNS。
- 当前 `U` 是时序、拥塞、线长和 HBT 的启发式加权值，不是官方评分。
- 实际全设计时序改善可能来自代理误差，也可能来自其他网络重布线后的间接受益；
  在做逐终点、逐路径对照之前，不将其中任何一种解释视为已验证原因。

下一版不以增加选网数量为目标。先提高候选排序与实际收益的一致性，再扩大搜索范围。
拥塞适合低成本粗筛，但不能替代终点时序收益；也没有证据表明它比当前廉价的
Elmore 代理在计算速度或选网质量上全面更优。

## 2. 范围、约束与阶段安排

保留 `mls_v1` 作为可复现对照，下一版建议使用独立的 `opt-code/mls_v2/` 入口、
配置和产物标签，继续复用 baseline 的两个 Die GRT、guide 校验及官方 evaluator。
新版本目录和下文新增导出接口均为计划项，当前尚未实现。

必须持续满足 [项目接口](../../README.md) 的约束：原始端点 Die、非 HBT 实例和
package pin 几何不变；原始 3D 网保持一个 HBT；采用 MLS 的原始 2D 网恰好使用
两个不同且合法的 HBT，形成一次借道再返回的连接。保持逻辑等价、die-local guides
及完整物理连通性，提交 ODB 不含 `dbWire` / `dbSWire`。

30% HBT 容量是数量评分阈值，初版将其用作保守预算，不是禁止超过的硬约束。
下一版先保留该预算策略；研究超阈值方案时单独比较真实收益与数量惩罚。

| 阶段 | 优先级与范围 | 工作内容 | 依赖与完成条件 |
|---|---|---|---|
| A | P0，下一版必做 | 无 MLS 基线、逐层资源/路由段导出、GRT 时序快照 | 与现有无 MLS 流程对照，导出不改变路由结果；数据口径可核对 |
| B | P0，下一版必做 | 按不同违例终点估计 TNS 收益，校准 RC、负载和关键性 | 依赖 A；能区分公共区段收益、终点重复、竞争路径及负收益 |
| C | P0，下一版必做 | H3D 启发的两 HBT 候选区域与接入代价 | 依赖 A/B；同等预算下与最近站点方案比较 |
| D | P0，下一版必做 | 少量候选实际 GRT/STA 验证、事务回滚、边际收益更新 | 依赖 A～C；接受依据来自重布线后反馈，失败可恢复 |
| E | P1，下一版独立实验开关 | 已有 HBT 重定位、Steiner 候选、站点冲突与局部交换 | 依赖 D；逐项消融，收益成立才进入默认配置 |
| F | P1，运行效率优化 | 增量 GRT/STA、静态缓存、CPU 批处理 | 依赖正确性对照；资源与时序结果不因遗漏背景网而失真 |
| G | P2，后续研究 | 全层局部异构图、受约束树上 DP、历史拥塞协商 | 主线验证后再投入；不作为下一版首个可运行版本的前置条件 |

## 3. 阶段 A：接入真实 GRT 反馈

### 3.1 输入来源与运行流程

赛事输入包含布局和连接关系、LEF、Liberty、SDC、RC 及布线配置，但不直接包含
实际 GRT 路径、资源占用和 overflow。所需反馈由算法在给定输入上运行一次无新增
MLS 的基线流程产生；不依赖外部设计数据或预先提供的 DRT 结果。

```text
规定输入
  → 无 MLS 的 Bottom/Top GRT
  → 分别保存逐层资源、实际路由段，建立合并后的时序快照
  → 候选生成与粗筛
  → 从同一已接受状态试运行少量候选的 GRT/STA
  → 接受并更新反馈，或回滚
  → 合并、校验并输出 5_1_grt.odb
  → 官方 evaluator 验证最终指标
```

基线 GRT、数据导出和候选试运行均计入算法耗时。开发时可以复用缓存，但正式
运行所需的预计算不能作为不计时的外部输入。缓存必须校验输入、配置和工具版本。

### 3.2 导出内容与接入位置

| 数据 | 导出内容 | 用途 |
|---|---|---|
| 逐层资源 | 网格坐标、层/Die、方向、capacity、demand、blockage、overflow | 定位热点，计算候选的真实资源增量 |
| 实际路由 | 原网/子网标识、wire/via 段、pin 接入及连通关系 | 重建候选区段，替代 RMST/L 路径背景需求 |
| 物理约束 | HBT 晶格与占用、宏块/OBS、pin shape、via 接入与层规则 | 排除不可实现的候选，估计接入代价 |
| 时序快照 | 终点 slack、关键路径及经过分支、driver/sink 数据、分析条件 | 建立终点收益映射，验证候选时序变化 |

在 `baseline/flow_scripts/scripts_3D/global_route_single_pass.tcl` 的每个 Die pass
结束时导出并保存数据，避免两个隔离进程的资源信息在 guide 合并时丢失。
已有 `write_global_route_segments` 和 FastRoute 的 `updateDbCongestion()` 可作
接入起点；它们不等于已经提供了完整的候选反馈接口。

需要核对导出字段的口径，特别是 blockage 是否已计入 usage/capacity，不能重复扣除。
需求覆盖所有实际参与布线的背景网，包括未进入 MLS 候选池的网络。候选评估先释放
旧网资源，再加入新子网；共享边与 via 占用按后端口径处理。

逐层读取资源不要求立即重写全层 router。第一步可以在真实路径与热点邻域上评分，
后续再扩展显式 `(gx, gy, layer, die)` 搜索图。

## 4. 阶段 B：以终点 TNS 贡献驱动选网和子网划分

### 4.1 正确的收益单位

OpenSTA 的 TNS 按终点累加负 slack，每个终点取最差 slack，而不是将所有负 slack
路径逐条累加。分析必须使用与 evaluator 一致的 setup、corner/mode 和约束口径，
不能自行把多个分析场景重复相加。参见 [OpenSTA 接口定义](https://github.com/The-OpenROAD-Project/OpenSTA/blob/master/include/sta/Search.hh)。

“上游、子节点多”的价值来自公共区段可能影响多个不同违例终点，不来自逻辑深度或
直接 fanout 本身。快速筛选应统计**实际受该分支延迟影响的不同违例终点**：

- 多条路径汇聚到同一终点时去重；只在非关键支路上出现不代表能改善该终点。
- Reg-to-reg 分析在捕获寄存器处截止，不累计后续流水级；其余受约束的 I/O 路径
  仍按实际 TNS 统计范围处理，尊重 false path、multicycle 等时序例外。
- 终点改善到零后，不再产生 TNS 收益；其他竞争路径可能提前限制收益。
- 同样改善 1 ps、且改善后仍为负时，每个终点对 TNS 的边际贡献相同。
  不能把负 slack 的绝对值直接当作精确 TNS 权重；WNS 目标单独表达。

例如：公共区段改善 10 ps，若使 20 个不同终点的最差 slack 各改善 10 ps 且仍为负，
TNS 改善为 200 ps。若同一终点两条路径分别为 −100 ps、−95 ps，只改善第一条
20 ps，最终 slack 只改善 5 ps。

### 4.2 候选收益模型

对候选 `c`，设当前终点 slack 为 `s_e`，预计变化为 `Δs_e(c)`，正值表示改善：

```text
ΔTNS_hat(c) = Σ[e ∈ E_affected]
             { min(0, s_e + Δs_e(c)) − min(0, s_e) }
```

`E_affected` 包括所有可能受影响的终点，而不只是选中分支的原负 slack 终点；
例如原来接近零的正 slack 终点可能退化为负。收益必须扣除这些损失。
同一终点只计一次，但其新 slack 必须考虑受影响路径与未改善的竞争路径。

当前 `prepare.tcl::criticalities` 仅对采样路径经过的 pin 保留最大关键性，
`planner.py::timing` 又只取最大加权 sink 延迟，不能表达终点数量差异。
下一版不能仅把 `max` 改成路径 `sum`；要新增终点标识、slack、分支映射和预测变化。

粗筛以“有效违例终点覆盖 × 可实现延迟改善”估计候选价值；精排使用上述终点收益。
跨网比较采用 ps/ns 的绝对预计改善，再按统一尺度归一化，不按每个网自己的旧延迟
归一化。否则改善比例大的小延迟网络可能压过全设计贡献更大的网络。

### 4.3 数据提取与精排

1. 导出终点 slack；为候选建立“driver→sink 分支→终点”的稀疏映射。
   初期使用每终点最差路径及有预算的近关键竞争路径，不枚举全部组合路径。
2. 当前 `-group_path_count 1000` 是有截断的路径采样，不能冒充完整 TNS 覆盖。
   记录采样终点数、违例终点覆盖率、覆盖的负 slack 总量及路径/内存预算；
   大设计采用按时序组、候选区域分批提取，截断时明确标记近似。
3. 用实际金属/via RC、sink pin 电容和驱动 slew/load 模型替换未校准常数。
   初期可保留经校准的 Elmore 粗筛，精排交给 OpenSTA。
4. 对候选计算所有 sink 的延迟变化，包括没有被移入目标分支的 sinks；新增 HBT
   和负载变化也可能通过公共驱动影响它们。再沿时序图传播，或执行增量 STA。
5. 以 GRT 寄生估计建立中间时序反馈，并核对已有/新增 HBT 的电气模型。
   HBT 每个 `3 Ω + 两端各 0.3 fF` 只计一次，接入 via RC 单独计入；不能默认
   原有 HBT buffer 的 Liberty 模型自动等价于 evaluator 的最终电阻模型。
6. 每接受一个方案，更新时序快照和候选的边际收益。多个候选影响同一终点时，
   不把各自基于旧基线的预测改善直接相加。

GRT/STA 反馈仍是 DRT 前估计，最终 TNS/WNS 由官方 evaluator 确认。保留独立的
WNS 目标或可配置退化限制，并检查 hold、slew、负载变化；这些保护策略与赛题
硬约束分开记录。Elmore 依赖下游电容，不能作为独立边权简单相加后声称全局最优。

## 5. 阶段 C：借鉴 H3D 改进 HBT 候选与接入

H3D 值得借鉴的是分开表达 routing/HBT 资源、利用树拓扑生成有利位置区域，再在
合法站点中优化位置。其论文目标和本文扩展的终点 TNS 目标不同；算法原理见
[H3D III-B～III-E](https://www.cse.cuhk.edu.hk/~byu/papers/C297-ICCAD2025-3DRoute.pdf)。

当前 `SiteMap.nearby()` 只在切分边两端附近各保留最近的 3 个合法点，`plan_net()`
已经联合枚举两端组合。下一步重点是扩大有价值的候选覆盖，不是为了使用 DP
而替换一个规模很小的候选对枚举。

计划按以下顺序构造候选：

1. 根据源侧、目标侧完整子树和真实热点区段，生成低线长接入区域；不只围绕
   RMST 边的两个原始 pin。保留原方案作为候选，便于直接对照。
2. 搜索区域内及周围方向的合法站点，并加入避开拥塞、接入条件较好的候选。
   采用空间索引和自适应候选预算，站点不足时有界扩大区域。
3. 联合比较两个 HBT，代价覆盖两侧完整子树、Top 路径、HBT/via 接入、逐层
   资源变化和终点时序收益；检查二者之间及与已有 HBT 的间距冲突。
4. 逐步加入真实 pin shape、OBS、cut spacing、PRL 和 via-stack 接入检查。
   几何合法不等于 DRT 可布通，可参考 CUGR 的概率资源/可布通性成本。

Manhattan 几何区域用于候选生成或下界剪枝。加入拥塞、离散障碍和时序后，不能
沿用纯线长问题的凸性来保证新目标最优；严格剪枝须使用可证明的下界，否则保留
候选数限制并标记为启发式。

## 6. 阶段 D：让规划结果接受实际布线检验

初版的 `top_corridor_edges` 只用于评分，没有传给 FastRoute。下一版先通过真实
重布线反馈形成闭环，再研究更强的路径控制：

- 粗筛后，仅对配置预算内的高价值候选，从同一已接受状态试提交、GRT、更新
  寄生并运行 STA。记录预测路径与实际路径、预测收益与实际中间指标的差异。
- 增量接口需验证能维护背景资源和其他网络状态，不能仅把子网列表传给空白 router
  就当作增量布线。尚未验证时，用少量候选的完整两 pass 重跑作为正确性对照。
- 若需要走廊约束，在 FastRoute 内实现区段、层和接入引导，并验证 guide 覆盖与
  连通性。不能把 Python 粗网格路径直接写成未经验证的最终 guide。
- 拒绝候选或试运行失败时，恢复 ODB 连接、HBT、资源、路由和 STA 状态；接受后
  才更新当前解。最终校验失败时，有界回退到已验证的可用解，并保留失败记录。

候选综合评分改用统一尺度的 `ΔTNS`、`ΔWNS`、拥塞变化、线长、HBT 数和接入风险。
各项权重、归一化尺度及保护阈值记录在配置和计划产物中，不宣称等价于官方评分。
同轮候选使用相同的当前解和归一化尺度。只有重布线后的综合收益超过配置阈值、
且满足合法性和所设时序保护条件时才接受，否则恢复当前解。实际 DRC 及最终得分
仍需完整官方评估；不把 GRT/STA 试运行通过等同于最终评估通过。

## 7. 阶段 E/F：独立实验与运行效率

### 7.1 已有 HBT 重定位

当前已有 HBT 只作为固定占用。`bp_fe` 基线有 1149 个 HBT，默认 MLS 只新增
8 个；已有 HBT 是更大的候选集合，但规模本身不证明收益更大。

新增独立开关，先对关键或拥塞原始 3D 网移动其已有 HBT，保持数量、标识及逻辑
连接约束，重布线两侧子网并校验时序。移动时释放旧站点、检查新站点、事务提交，
与新增 MLS 分开消融。后续允许已选 MLS 的两个 HBT 联合重定位。

### 7.2 路由树与 Steiner 候选

优先复用真实基线路由树，识别共享主干和内部接入点；实际路由重建时检查连通性、
重复段及环，不将任意路由段集合直接当作 RC 树。无可用路由树时接入 FLUTE，
保留 RMST 对照。让候选切分覆盖内部 Steiner 点和拥塞区段，而不只考虑最长的
少量 pin-to-pin 边。

Steiner 拓扑可能同时影响候选质量和成本估计，应分项记录构造时间、候选数量和
最终收益；不因换用 FLUTE 就假定最终 DRT 线长必然下降。

### 7.3 候选冲突、交换与协商

每个 MLS 候选同时占用两个站点，不能拆成两次独立最近邻或普通二分匹配。
初期保留逐网接受，但在接受后刷新资源、终点收益和受影响候选排序，并增加有预算的
1↔1 / 1↔2 局部交换。可对稀缺站点引入占用价格，减少低收益方案抢占其他网络
少数可用接入位置的情况，价格变化后重新评估候选。

小区域可将候选设为二元变量 `x_p`，以当前边际收益 `U_p` 最大化 `Σ U_p x_p`，
约束每网至多一个候选、相互冲突候选不能共存，以及新增 HBT 总预算。互斥范围包含
站点及 pitch 邻域；routing capacity 和终点收益相互作用仍需组合重评，不能假定
静态 `U_p` 可精确相加。整数规划/最大权独立集作为可选实现，单 HBT 的独立分配
子问题才考虑最小费用流或 Hungarian。

后续借鉴 PathFinder 的当前/历史拥塞价格，对热点做迭代替换和重定位；限制迭代
次数，记录收益曲线，不把 FPGA 路由方法直接视为本题 router 的替代品。

### 7.4 增量与缓存

在完整重跑对照成立后，只更新受影响子网和拥塞邻域，并复用增量 STA。
缓存静态 tracks、OBS、合法站点索引及可复用路径查询；HBT 移动、网络改变或
资源变化后失效相关缓存。分别配置粗筛、候选对、A*、STA/GRT 试运行和总时间预算。

优先研究 pattern routing 批处理、任务依赖和 CPU 并行，不默认 GPU 可用；
FastGR/InstantGR 作为方法参考。遵守赛题最多 32 线程，避免并发用例共享流程工作
目录产生覆盖。重点测量 `bp_quad` 的端点映射内存、导出量和候选验证时间。

## 8. 阶段 G：受约束树上 DP 与全层搜索

对一个全部 pin 在同一 Die 的原始 2D 网，直接最小化 HBT 数量会得到零 HBT，
因此不能原样套用 H3D 的数量优化目标。必须比较“不做 MLS”与“恰好两个 HBT
借道后返回”的方案，不允许把两个必需 HBT 合并为一个。

后续局部图显式区分 wire、via 和 HBT 边，以原始端点 Die 固定为边界条件。
树上 DP 的状态至少包含节点/连接所属 Die、已用 HBT 数 `h ∈ {0,1,2}` 和连通模式。
树边内部要允许插入接入节点；仅给 pin 节点重新分配 Die 不足以表达借道。
最终接受状态为原始 2D 网的 `h=0` 或合法 MLS 的 `h=2`，原始 3D 网仍遵守单 HBT
约束，不将一般树的跨 Die 次数自由度带入竞赛接口。

先用可组合的线长、资源和接入成本生成少量拓扑，再用完整 RC/STA 精排。
若把时序直接纳入 DP，需要额外处理下游电容、slew 和竞争路径状态，不承诺简单
标量 DP 能得到最优 TNS。全层搜索仅在有明确质量收益且运行预算允许时启用。

## 9. 实现产物与验收计划

### 9.1 代码与产物安排

| 位置/组件 | 计划改动 |
|---|---|
| baseline 的各 Die GRT pass | 可选反馈导出；关闭时保持现有流程行为 |
| 下一版 `prepare.tcl` | 分阶段加载反馈，导出终点/分支/RC 信息，支持可回滚试提交及 HBT 移动 |
| 下一版 Python 规划器 | 逐层资源读入、终点收益映射、区域站点候选、边际排序与交换 |
| 下一版运行脚本 | 基线反馈、候选验证、最终输出的阶段编排与预算控制 |
| 计划 JSON / 诊断报告 | 版本化反馈格式、候选分项收益、终点覆盖、模型误差、接受/拒绝原因与耗时 |

每个候选至少记录操作类型、原网/分支、HBT 位置与数量变化、受影响终点及去重规则、
预测/验证的 TNS/WNS/拥塞/线长变化、路径采样覆盖和所用模型。记录试运行失败、
回滚和搜索预算耗尽，不能只保存成功候选。

### 9.2 正确性检查

实现时增加针对以下边界情况的测试：

- 终点收益：多终点公共区段、同终点多路径去重、竞争路径接管、跨零截断、原正
  slack 终点退化、多个候选重叠、未选 sink 受负载影响及时序例外。
- 资源与站点：释放/新增资源守恒、blockage 口径、站点互斥、移动释放旧占用、
  两 HBT 链与原始 3D 单 HBT 约束。
- 流程：试提交故障后完整恢复、增量与完整重跑对照、guide 层归属/覆盖/连通性，
  以及实际 OpenDB 中的几何与逻辑保持检查。

### 9.3 实验顺序与放行依据

1. 固定输入哈希、镜像 ID、overlay、线程数、FastRoute 参数、DRT 迭代数及机器
   条件。重建无 MLS 基线和 `mls_v1` 对照；导出开启/关闭先核对路由一致性。
2. 在 `bp_fe` 从一个候选开始，逐项启用真实资源、终点 TNS 权重、实际 RC、
   区域站点和 GRT/STA 验证。初期保持相同候选/HBT 预算，隔离各项收益。
3. 分别测试已有 HBT 重定位、Steiner 拓扑、候选交换及增量执行；设置“仅拥塞
   粗筛 / 当前时序代理 / 终点收益 / 联合方案”对照，比较筛选质量与计算成本。
4. 对有代表性的接受和拒绝候选做离线官方评测，核对预测方向、排序相关性、
   误接受/漏选率及逐终点 slack 变化；不把 GRT overflow 当成最终 DRC。
5. 选定配置后逐 case 扩展到 `ariane133`、`ariane136`、`bp`、`bp_fe`、`bp_be`、
   `bp_multi`、`swerv_wrapper`、`bp_quad`，采用留一用例等方式检查参数稳健性，
   不按 case/net 名称定制算法。保存所有失败与退化结果。

每次记录 TNS、WNS、DRT 线长、DRC、HBT 数及超阈值数量，并分别记录基线 GRT、
导出、规划、候选 GRT/STA、最终 GRT、evaluator 时间和峰值内存。
`evaluator_runtime_seconds` 不能代替算法/GRT 总耗时，新增预计算必须计入。

下一版默认方案的放行条件是：完整官方合法性和物理连通性检查通过；在固定实验
条件下报告八例指标与时间的分布及退化情况；候选排序和最终质量的收益有消融证据。
不预设论文中的改善比例，不要求每个指标同时单调改善，也不以单例 TNS 改善掩盖
WNS/DRC/时间退化。P1 模块若收益不稳定，保留为关闭的实验开关；P2 不阻塞主线交付。
